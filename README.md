# 学搭子 · Demo 1.0

> 长视频自学场景下的 AI 伴学陪练（设计型项目 · Final Project Demo 1.0）
> **核心 Learning Goal**：学生能在**没有 AI 的情况下**把一条一小时以上的长视频独立学完学实
> ——自己把视频拆成学习单元、每学完一段先自我解释、再用自测定位薄弱点，一周后仍能提取并迁移。

## 怎么体验（不需要安装、不需要密钥）

下载本仓库中的 `index.html`，**双击用浏览器打开**即可（也就是本页那个链接里的页面）。
单文件自包含，AI 的语言由内置规则引擎实时生成，任何人打开就能跑完整流程。

当前 Demo 用的是**真实视频**：[《高等数学(上)》期末3小时通关·上集](https://www.bilibili.com/video/BV1CC4y1T72s)
（时长 89.6 分钟、字幕 2372 条；Demo 取其中前 6 个学习片段）。页面左侧嵌入原视频播放器，右侧是伴学侧栏。

**90 秒走完一轮**（课堂演示脚本）：

1. 点"▶ 播放（模拟 8×）"看一段讲解，或直接点"看完了，进入『我先说』"
2. 写下你自己的理解 → AI **判读**（长度 / 与原文重合率 / 是否有因果表述），据此决定介入方式
   - 写太短 → 给思考框架（仍**不给答案**）
   - 粘贴原文 → 判为复述，要求换自己的话说
   - 说清楚 → 只确认，直接进小测
3. 做 2 题检索小测 → AI **只报对错与时间戳，不解释**；错题进回顾清单
4. 点"⚡ 我被打断了（模拟消息）" → AI 留下一条**未闭合的回路**（未答完的题 + 进度）
5. 点"↩ 我回来了" → 先做**两题冷启动**（1 题上段回顾 + 1 题上次没答完的）；可跳过，跳过会被记录
6. 走到最后看**学习报告**：过程指标与结果指标分开；右下角可导出 JSON 埋点日志

页面右上角实时显示**支持档位**：连续"先说清楚 + 小测全对"就降一档
（L3 给框架 → L2 只追问 → L1 只在求助时提示 → L0 只出题）。降到 L0 时 AI 连"先说一遍"都不再要求——
这就是支持递减与最终撤出的原型。

## 文件说明

| 文件 | 作用 |
| --- | --- |
| `index.html` | **Demo 本体**（自包含；片段/题目/字幕时间戳已内嵌，打开即用） |
| `template.html` | 页面模板，用 `/*__SEGMENTS__*/` 占位 |
| `bili_pipeline.py` | 数据管线：字幕 → 学习片段 → 检索式小测题（切段 + 术语打分） |
| `build_from_subs.py` | 把取到的真实字幕 JSON 转成 Demo 数据，支持人工校验层 |
| `quiz_overrides.json` | **人工校验层**：逐段替换自动出题结果（当前 12 道全部为人工题） |
| `subs_real.json` | 原始字幕留档（该视频 2372 条，公开信息，不含任何账号数据） |
| `segments.json` | 当前 Demo 使用的片段/题目数据（真实字幕版） |
| `segments_mock.json` | 演示讲稿版数据（不依赖任何平台，可离线复现） |

## 数据是怎么来的（字幕不落 cookie 的做法）

B站字幕接口需要登录态（未登录返回空列表，看起来像"这视频没字幕"）。本项目**不导出 cookie 文件**，
而是在**已登录的浏览器会话里做同源 fetch**取字幕，取到后立刻转成数据文件：

```bash
# 1) 在浏览器登录态下取字幕 → 得到 subs_real.json（含 meta 与 subtitle.body）
# 2) 真实字幕 → 片段+题目（自动层），再用人工校验层覆盖
uv run --with jieba python build_from_subs.py subs_real.json \
    --overrides quiz_overrides.json -o segments_real.json --max-segments 6

# 3) 注入模板，生成可分享的单文件 Demo
python3 - <<'PY'
import json
tpl = open('template.html', encoding='utf-8').read()
d = json.load(open('segments_real.json', encoding='utf-8'))
open('index.html','w',encoding='utf-8').write(
    tpl.replace('/*__SEGMENTS__*/','window.SEGMENTS = '+json.dumps(d,ensure_ascii=False)+';'))
PY

# 回到"演示讲稿版"（完全不依赖平台）：bili_pipeline.py --mock 生成 segments_mock.json 后灌进去即可
```

## 已知局限（第一次真实运行后发现的）

1. **自动出题在真实 ASR 字幕上明显退化**（实测）：AI 字幕没有标点、句子连成串，自动层抓出来的
   12 道里只有 1 道能用（"保号性"），其余是"基本上""表达式""表面"这类无意义的空。
   → 因此加了**人工校验层**（`quiz_overrides.json`），当前 12 道题全部人工过了一遍。
   **这不是补丁，是设计的一部分**：题库质量直接决定测量效度。
2. **判读不校验"说的对不对"**：同一段解释粘贴到别的片段，判读仍给"清楚"——它只看长度、
   重合率、因果词。真实版本必须加"与本段关键词覆盖率"或 LLM 判读，否则会奖励说套话的学生。
3. **支持递减太快**：连续三段就 L3 → L0。真实实验里应要求"连续两段 + 跨视频"才降档。
4. **"因果表述"检测会被原文污染**：粘贴原文时也判出"因果 有"（原文含"如果……就"），
   所以现在把"与原文重合率"作为优先判据。
5. **跳过是流程的第一个死穴**（已修）：最初跳过后不推进题号，学生一跳过整条流程就卡死。
   真实数据里跳过率不会低，设计上必须"允许跳过 + 流程绝不中断"。
6. **当堂反馈会被下一段冲掉**（已修）：答完最后一题直接进下一段，学生看不到反馈与错题；
   现在改为先出"段小结 + 错题清单"再进下一段。
7. **时间轴是模拟的**（8×），"点回原处"目前是高亮对应字幕行、时间戳与真视频一致，但不会
   自动跳转播放位置；真实版本要接 B站播放器 API 做精确 seek。

## 课堂展示要回答的三个问题（简版）

- **核心 Learning Goal**：见开头一句话——判据是"撤掉 AI、换成新视频之后学生还会不会这样学"。
- **已经真正做出来的部分**：真实字幕管线 → 片段与题库 → 判读与支持强度决策 → 支持递减（L3→L0）→
  检索小测与错题清单 → 中断留回路 → 返回冷启动 → 学习报告与 JSON 埋点导出，
  全部在同一份可分享的页面里真实运行。
- **第一次运行发现的要改的地方**：见上面 7 条，其中 1、2、3 会直接影响测量的有效性。
